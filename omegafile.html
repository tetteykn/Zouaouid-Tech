The problem Windows doesn't tell you about

You copy a folder, walk away, come back twenty minutes later and it still isn't done — even though the folder is only a few gigabytes. Meanwhile a single 20 GB video copied last week finished in under two minutes.

The answer has nothing to do with total size or drive speed. It has everything to do with the number of files.

Windows processes each file individually — open, read, write, close, move on. For one large file that's fine. But a folder of thousands of small files makes Windows repeat that entire sequence thousands of times, each one costing multiple calls into the OS kernel plus a separate disk operation for metadata. With 10,000 files that's potentially 80,000–100,000 individual system operations before a single byte of your actual data has finished moving.

That is why a folder with 50,000 small files totalling just 1 GB can take over an hour in Windows, while a 20 GB video copies in minutes. The bottleneck isn't your disk — it's the way Windows handles each file one at a time. OmegaFile solves this completely.

How it copies so much faster

OmegaFile uses an adaptive copy engine that picks the best strategy for what you are copying. You never choose — it detects and decides instantly.

Single file

Strategy A

Uses Windows' native CopyFileEx API directly — the most efficient path possible for one file, with real-time progress reporting so you always see exactly how far along the copy is.

Small collections

Strategy B · under 1,000 files

Runs 8 parallel copy workers at once. Instead of waiting for file #1 before starting file #2, all eight copy different files simultaneously. On a modern SSD this alone delivers a significant speedup.

Large collections

Strategy C · up to 100,000 files

Uses IOCP (I/O Completion Ports) — the same technology inside high-performance web servers and database engines. Up to 24 copy operations are submitted to the OS simultaneously and completions are processed as they arrive, keeping the disk queue full so data moves without gaps.

Extreme collections

Strategy D · 100,000+ files

Switches to a turbo stream mode. Files are processed in large batches flowing through the system as a continuous data stream rather than individual operations, bypassing most per-file overhead and scaling to millions of files without degrading.

Force Delete

Remove files Windows refuses to touch.

Windows sometimes refuses to delete files. You see errors like "The file is open in another program", "Access is denied", or "You need administrator permission" — even when no program is visibly using the file.

OmegaFile's Force Delete handles all of these cases. It takes ownership of the file, strips all blocking attributes, closes any open handles it can reach, and removes the item.

For files so deeply locked that even these steps cannot free them, OmegaFile schedules them for automatic deletion the next time Windows restarts — the file is gone on next boot, with no manual steps required.

Key features

Intelligent adaptive copying

OmegaFile scans your selection in under a second, counts the files, measures the total size, and automatically picks the right strategy. No settings to configure, no modes to select — it just works.

Handles file moves as well as copies. Moving between folders on the same drive uses the fastest available path; moving between drives copies then deletes, giving you progress feedback the whole time.

When Windows copy is fine

The advantage is most visible when copying more than a few hundred files, with deep subfolder structures, of small files under 1 MB each — especially when Windows shows an estimate of several minutes for data under 1 GB.

For everyday simple copies — one document, a few photos — Windows copy is perfectly adequate.
